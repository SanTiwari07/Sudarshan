# SUDARSHAN – Current System Architecture

> **Source of truth**: Generated by auditing the live codebase.
> Last audited: 2026-08-25.

---

## 1. System Overview

SUDARSHAN is an enterprise Android APK threat-intelligence platform for banking security
operations. It combines static analysis, Frida-based dynamic sandbox analysis,
AI-assisted investigation, threat correlation, deterministic risk scoring, and report
generation into a single platform.

**Four runtime processes** are orchestrated via Docker Compose:

| Process | Role |
|---|---|
| **backend** (FastAPI :8000) | API gateway, auth, job queue, SQLite DB, LLM calls, STIX/IOC export |
| **analysis-engine** (FastAPI :8001) | Isolated static + dynamic analysis microservice |
| **frontend** (Vite/React) | Single-page React application |
| **MobSF** (external, optional) | Deep static analysis engine (only if `MOBSF_HOST` configured) |

The emulator (Genymotion Desktop or Android Studio AVD) runs on the **host machine**,
not inside any container. The analysis-engine container reaches it via ADB over the
Docker host network.

## 4. End-to-End Scan Lifecycle

### 4.1 Normal Path (analysis-engine available)

```
POST /api/v1/analyze (multipart APK upload)
  |
  +-- Validate: extension check + ZIP magic bytes + size limit + SHA256 hash
  |
  +-- POST http://analysis-engine:8001/api/v1/analyze
  |    Body: {file_path, sha256} + ANALYSIS_ENGINE_INTERNAL_TOKEN header
  |
  |   Inside Analysis Engine:
  |   +-- Androguard static analysis         (always)
  |   +-- MobSF static analysis              (if MOBSF_HOST set)
  |   +-- APKTool enrichment                 (if apktool installed in container)
  |   +-- JADX enrichment                   (if jadx installed in container)
  |   +-- InvestigationManifest build
  |   +-- Frida dynamic sandbox              (if emulator ready)
  |   |    +-- Agentic Explorer (exploration_engine.py)
  |   +-- VIDE analysis
  |   +-- calculate_risk_score()
  |   +-- Return raw result dict
  |
  +-- Backend _enrich_engine_result():
  |   +-- classify_family()                  (rule-based)
  |   +-- analyze_with_llm()                 (Gemini Flash)
  |   +-- save_case() + cache_report() + build_investigation_index()
  |
  +-- Return AnalysisResponse JSON

GET /api/v1/report/html/{sha256}   --> HTML report (self-contained)
GET /api/v1/report/pdf/{sha256}    --> PDF report
GET /api/v1/report/stix/{sha256}   --> STIX 2.1 JSON bundle
GET /api/v1/report/iocs/{sha256}   --> IOC CSV
```

### 4.2 Fallback Path (analysis-engine unavailable)

- If `SUDARSHAN_ALLOW_GATEWAY_DYNAMIC=true`: backend runs local pipeline (Androguard only, no APKTool/JADX, no container limits). **Logged as WARNING.**
- If `SUDARSHAN_ALLOW_GATEWAY_DYNAMIC=false` (production default): HTTP 503 returned.

### 4.3 Async Path

```
POST /api/v1/analyze/async  -->  {job_id}
GET  /api/v1/status/{job_id}  -->  poll job status + result
```
An asyncio worker pool processes jobs; pipeline is identical to sync path.

## 5. Static Analysis Pipeline

```
APK file
  |
  +-- Androguard (always, sudarshan_core/analyzers/apk_analyzer.py)
  |   +-- Package name, permissions list
  |   +-- Dangerous API detection:
  |   |     addJavascriptInterface, Runtime.exec, ProcessBuilder.start,
  |   |     DexClassLoader, PathClassLoader, System.loadLibrary
  |   +-- Reflection API detection:
  |   |     forName, getDeclaredMethod, getDeclaredField, invoke, newInstance
  |   +-- URL / IP extraction (regex on string pool)
  |   +-- Indian banking package matching (21 known prefixes, boundary-safe algorithm)
  |   +-- Shannon entropy obfuscation scoring (0.0 to 1.0)
  |   +-- Concealed payload detection (nested APK/DEX in assets)
  |   +-- Suspicious string extraction
  |   --> AndroguardOutput: package_name, permissions, StaticAnalysisFlags, app_label
  |
  +-- MobSF (optional, if MOBSF_HOST configured)
  |   +-- manifest_analysis  --> ManifestFinding[]
  |   +-- code_analysis      --> CodeFinding[]
  |   +-- Exported activities, services, receivers, providers
  |   +-- Certificate details
  |   +-- Domain map, email list
  |   +-- Binary analysis results
  |   +-- Network security config
  |   +-- Tracker detection
  |   +-- AppSec score
  |   --> Raw MobSF report dict; flags merged into flags_dict
  |
  +-- APKTool (optional, if installed in analysis-engine)
  |   +-- Decoded resource strings
  |   +-- Obfuscated resource count
  |   +-- Suspicious resource detection
  |   +-- UI profile (layout XMLs) for VIDE
  |
  +-- JADX (optional, if installed in analysis-engine)
  |   +-- Fraud class hits: ACCESSIBILITY_SERVICE, SMS_RECEIVER,
  |   |     OVERLAY_WINDOW, OVERLAY_DRAW, DEVICE_ADMIN, DYNAMIC_CLASS_LOAD
  |   +-- Decompiled suspicious strings
  |
  +-- VIDE Visual Impersonation Detection Engine (engines/vide/)
      +-- Signing certificate check (signer_registry.py)
      +-- Color palette extraction and baseline comparison
      +-- Layout XML / view AST analysis (ast_builders.py)
      +-- DEX string corpus comparison
      +-- Aggregate corpus score vs. CORPUS_DETECTION_THRESHOLD
      --> VIDECompareResult: visual_impersonation_detected, confidence, institution
```

## 6. Dynamic Analysis Pipeline

### 6.1 Emulator Lifecycle

1. `SandboxProvider.auto_detect()` fingerprints connected ADB devices (Genymotion / AVD / physical)
2. Verify ADB connectivity, root access, frida-server deployment
3. frida-server: deployed to `/data/local/tmp/`, started as root (auto-downloaded if not cached)
4. `adb install -r -t <apk>` with retry and APK repair (`apk_repair.py`)
5. Pre-grant all declared runtime permissions via `pm grant` (when `SUDARSHAN_PREGRANT_PERMISSIONS=1`, default on)
6. `adb shell am start -n <package>/<activity>` — waits up to `SUDARSHAN_APP_OPEN_SETTLE=8.0s`
7. Cleanup: APK uninstalled; artifact directory preserved

### 6.2 Frida Hook Attachment

`frida_sandbox.py` hooks:
- Accessibility service registration
- SMS read / receive / send
- Overlay window creation (WindowManager)
- Network connections (OkHttp, HttpURLConnection)
- Contact reads
- File access
- Crypto operations
- Device admin activation
- Banking package targeting detection

Events flow through `RuntimeEventBus` → `EvidenceStore`. YARA scanner runs against memory. `AntiAnalysisDetector` monitors for emulator detection by the target.

### 6.3 Agentic Deep Exploration Engine

`exploration_engine.py` (1774 lines) drives deterministic state-graph exploration with AI-assisted prioritization.

**State graph nodes** (`ExplorationState`):
- `state_id`, `screen_hash`, `ui_tree_hash`
- `activity_name`, `package_name`, `foreground_package`
- `semantic_type`, `ownership`
- `actionable_elements: List[ActionItem]`
- `visit_count` (capped at `MAX_REPEATED_STATE_VISITS=5`)

**State identity**: SHA-256 of `activity + package + ui_tree_fingerprint`

**State graph edges** (`ExplorationEdge`):
- `source_state_id` → `target_state_id`
- `action_type`, `pre_state_hash`, `post_state_hash`
- `ui_changed`, `new_actions_found`, `runtime_event_count`

**Exploration budgets** (all env-configurable):

| Variable | Default | Meaning |
|---|---|---|
| `SUDARSHAN_AGENT_ACTION_BUDGET` | 60 | Total actions allowed |
| `SUDARSHAN_MAX_EXPLORATION_STATES` | 200 | Unique states |
| `SUDARSHAN_MAX_EXPLORATION_DEPTH` | 25 | BFS depth |
| `SUDARSHAN_MAX_REPEATED_STATE_VISITS` | 5 | Revisit limit per state |
| `SUDARSHAN_MAX_SCROLL_DEPTH` | 8 | Scroll iterations per region |
| `SUDARSHAN_MAX_BACKTRACKS` | 20 | Backtrack steps |
| `SUDARSHAN_MAX_ACTION_RETRIES` | 3 | Retries per action |
| `SUDARSHAN_AGENT_SILENCE_THRESHOLD` | 8 | Consecutive no-Frida-event actions before backtrack |

**Stopping conditions** (`StopReason` enum):

| Reason | Meaning |
|---|---|
| `EXPLORATION_COMPLETE` | All reachable states exhausted |
| `EXPLORATION_BUDGET_EXHAUSTED` | Action/state/depth limit hit |
| `TIME_BUDGET_EXHAUSTED` | `FRIDA_ANALYSIS_DURATION` exceeded |
| `APPLICATION_CRASH_LOOP` | Repeated crashes exceed `MAX_CRASH_RECOVERY_ATTEMPTS` |
| `NO_UNEXPLORED_ACTIONS` | No unresolved actions remain |
| `SANDBOX_FAILURE` / `SANDBOX_BLOCKED` / `CANCELLED` / `FATAL_ERROR` | Error states |

### 6.4 Perception Pipeline (5 Levels)

`perception.py` — observations are built from up to 5 sources:

| Level | Source | Trigger |
|---|---|---|
| 1 | `uiautomator dump` XML | Always |
| 2 | `dumpsys activity` (current activity name) | Always |
| 3 | Frida runtime events from EventBus | Always |
| 4 | `adb logcat -d` tail (40 lines) | When no clickable nodes found |
| 5 | `adb shell screencap` + optional vision | See below |

**Screenshot (Level 5) triggers:**
- UI XML empty or parse failed
- Fewer than `MIN_ACTIONABLE_NODES=1` clickable elements found
- Labeled-node fraction < `LABELED_NODE_FRACTION_THRESHOLD=0.20`
- Activity is a known WebView class
- Previous action failed due to UI identification failure
- Frida events contain fraud categories (`overlay`, `accessibility`, `sms`)

**Output**: `Observation` dataclass — `activity`, `UINode[]`, `screen_hash`, `frida_events`, `logcat`, `screenshot_path`, `is_webview`, `is_empty_ui`.

### 6.5 Screen Classification

`screen_classifier.py` (rule-based, no LLM):

| ScreenType | Detection Logic |
|---|---|
| `BANK_LOGIN` | Input fields + bank/login/password keywords |
| `OTP_SCREEN` | OTP/verification code keywords |
| `ACCESSIBILITY_DIALOG` | Accessibility keywords in activity or text |
| `SYSTEM_PERMISSION` | GrantPermissionsActivity or allow/deny + permission |
| `OVERLAY_ATTACK` | Overlay/alertwindow keywords |
| `UPDATE_PROMPT` | Update/new version/install update keywords |
| `DOWNLOAD_PROMPT` | Download/fetch keywords |
| `PACKAGE_INSTALLER` | PackageInstaller activity or apk install keywords |
| `VPN_REQUEST` | VPN keywords |
| `WEBVIEW` | WebView activity class or http/https text |
| `DIALOG` | Dialog/alert keywords + few nodes |
| `SETTINGS` | Settings/preferences activity |
| `HOME` | MainActivity/HomeActivity/Launcher |
| `HOME_LAUNCHER` | Foreground package is a known system launcher |
| `EXTERNAL_APP` | Foreground package differs from target |
| `CRASH_STATE` | Crash-related activity markers |
| `APP_NOT_RESPONDING` | ANR indicators |
| `UNKNOWN` | Default fallback |

`classify_screen_with_ownership()` adds `ScreenOwnership` resolution. Safe interactive types on `EXTERNAL_APP` screens (system permission dialogs, install prompts) preserve their interactive type so the explorer can interact with them.

### 6.6 Action Discovery and Prioritization

`ActionPrioritizer.score_action()` deterministically scores each `ActionItem`:
- Base: 50
- Unresolved: +30; Failed: -40; Blocked: -50
- Security-relevant screens (accessibility/SMS/overlay): +80
- Affirmative tiebreaker (Yes/OK vs No/Cancel): +15
- Semantic role boosts (ACCEPTANCE_ROLE for high-priority interactions)
- Labeled buttons preferred; unlabeled full-screen containers pruned

`ActionDispatcher` translates `ActionItem` → `ExecutableAction` → `ToolExecutor` payload.

### 6.7 Action Execution Path

```
ActionItem
  |
  ActionDispatcher.dispatch()
    attempt=1  -> click_text (by text label)
    attempt>=2 -> tap (by coordinates)
  |
  ToolExecutor.execute(payload)
    Navigational tools wait for window idle (IDLE_WAIT_TIMEOUT=6s)
    POST_INPUT_SETTLE=0.6s floor after every input event
    Returns ToolResult(success, output, error)
  |
  SandboxProvider (adb shell input tap / type_text / scroll / press_back / ...)
  |
  UI state change on emulator
  |
  Next perception cycle
  |
  State hash comparison (pre vs. post)
  |
  ExplorationEdge recorded
```

All delays scaled by `SUDARSHAN_ACTION_DELAY_SCALE` (default 1.0; raise to 2.0 on slow emulators).

### 6.8 Progress Detection

After each action:
1. Compare `pre_state_hash` vs `post_state_hash`
2. Identical → action `failed=True`, retry counter incremented
3. After `MAX_RETRIES_PER_ACTION=3` failures → action `blocked=True`
4. If `FRIDA_SILENCE_THRESHOLD=8` consecutive actions produce no Frida events → backtrack triggered

### 6.9 Evidence Collection During Dynamic Analysis

| Evidence Type | Collection Mechanism |
|---|---|
| Screenshots | `ScreenshotManager` triggered by Level-5 perception policy + key events |
| UI hierarchy | XML dumps per observation |
| Frida runtime events | Hook fires from attached Frida script |
| API calls | Hooked Java methods with arguments |
| Network logs | OkHttp / HttpURLConnection interception |
| Files accessed | Filesystem read/write monitoring |
| Logcat tail | Captured at Level 4 when needed |
| Attack timeline | Timestamped event sequence |
| Evidence records | `EvidenceStore` entries (category, severity, description) |
| YARA matches | Runtime memory scanning |
| Anti-analysis events | Emulator detection / debugger checks |
| Permission triggers | Which declared permissions the app actually invoked |

## 7. AI / Gemini Pipeline

### 7.1 Provider Management (`gemini_provider.py`)

`GeminiProviderManager` implements a circuit-breaker failover:
- **Primary slot** tried first; exponential backoff on retryable errors
- **Cooldown** (`GEMINI_PRIMARY_COOLDOWN_SECONDS=60`): primary circuit opens after consecutive failures
- **Fallback slot** used when primary circuit is OPEN
- Both failing: `GeminiAllProvidersFailed` raised
- `GeminiCallResult.fallback_used` records which provider answered

**Configuration:**

| Variable | Default | Purpose |
|---|---|---|
| `GEMINI_PRIMARY_API_KEY` | — | Primary provider key |
| `GEMINI_PRIMARY_MODEL` | `gemini-3.6-flash` | Primary model |
| `GEMINI_FALLBACK_API_KEY` | — | Fallback provider key |
| `GEMINI_FALLBACK_MODEL` | `gemini-2.5-flash` | Fallback model |
| `GEMINI_MAX_RETRIES` | 3 | Per-provider retry limit |
| `GEMINI_RETRY_BASE_SECONDS` | 0.5 | Exponential backoff base |
| `GEMINI_PRIMARY_COOLDOWN_SECONDS` | 60 | Circuit open duration |

Legacy aliases: `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `GEMINI_MODEL`.
If primary and fallback keys are identical with identical models, fallback is disabled.

### 7.2 AI Call Sites

| Call Site | Purpose | Module |
|---|---|---|
| `analyze_with_llm()` | Narrative, fraud card, recommendations | `backend/app/ai/gemini_client.py` |
| `planner.py` AI planner | UI exploration action selection | `engines/agentic/planner.py` |
| `goal_planner.py` | Investigation goal generation per stage | `engines/agentic/goal_planner.py` |
| `semantic_matcher.py` | VIDE semantic enrichment (advisory) | `engines/vide/semantic_matcher.py` |
| `caption_generator.py` | Screenshot caption generation | `engines/agentic/caption_generator.py` |
| `artifact_explainer.py` | Evidence artifact explanation | `ai/artifact_explainer.py` |

### 7.3 Agentic Planner Fallback

When Gemini is unavailable: `FallbackPlanner` (deterministic, no LLM calls) takes over.
Exploration continues with rule-based action selection. Coverage is lower but the run completes.
This is an informational condition, not an error.

### 7.4 LLM Output Contract

`analyze_with_llm()` returns `intelligence_report` with:
- `plain_english_narrative`
- `executive_fraud_card` (FraudCardExecutiveView)
- `technical_fraud_card` (FraudCardTechnicalView)
- `fraud_scenario`, `fraud_scenario_details`
- `recommended_actions`
- `confidence`

Malformed/partial responses degrade gracefully to minimal narrative text. The AI does **not** contribute to FRS score — scoring is purely deterministic.

## 8. Risk / FRS Scoring

### 8.1 Top-Level Formula

```
FRS = 0.25 × STEI + 0.35 × Dynamic + 0.20 × Correlation + 0.20 × BankingImpact
```

When an axis is **excluded** (not conclusive), its weight is redistributed proportionally across included axes.

### 8.2 STEI – 5-Axis Formula

```
STEI = 0.60 × CT + 0.20 × BT + 0.10 × PR + 0.05 × OB + 0.05 × IR
```

**CT – Credential Theft** (weight 0.60):
- Accessibility service declared: +40
- SMS read/receive: +35
- System alert window: +25 | Cap: 100

**BT – Banking Targeting** (weight 0.20):
- Visual impersonation detected: `min(35 + confidence × 40, 85)`
- Indian bank packages matched: `20 + (count × 10)` | Cap: 100
- Uses boundary-safe package matching (prevents false substring hits)

**PR – Permission Risk** (weight 0.10):
Weighted sum: `BIND_ACCESSIBILITY_SERVICE=20`, `READ_SMS=18`, `RECEIVE_SMS=18`,
`REQUEST_INSTALL_PACKAGES=20`, `SYSTEM_ALERT_WINDOW=15`, `READ_CONTACTS=8`, … | Cap: 100

**OB – Obfuscation** (weight 0.05):
- DexClassLoader / PathClassLoader: +40
- System.loadLibrary: +20
- Java reflection (forName/invoke): +25
- Shannon entropy > 0.5: `(entropy - 0.5) × 30` (max +15)
- Concealed payload (nested APK/DEX in assets): +60 | Cap: 100

**IR – Infrastructure Risk** (weight 0.05):
`count(hardcoded_urls_ips) × 10` | Cap: 100

### 8.3 BFCI – Dynamic Behavioral Score (Frida path)

```
BFCI = 0.35×A + 0.25×S + 0.20×O + 0.10×B + 0.05×N + 0.05×P
```

| Component | Weight | Signal |
|---|---|---|
| A – Accessibility | 0.35 | Accessibility abuse score (0–100) |
| S – SMS | 0.25 | SMS interception score (0–100) |
| O – Overlay | 0.20 | Overlay attack score (0–100) |
| B – Banking | 0.10 | Banking interaction score (0–100) |
| N – Network | 0.05 | C2 communication score (0–100) |
| P – Persistence | 0.05 | Persistence mechanism score (0–100) |

Sandbox pre-computes component scores; risk engine validates range [0–100] before use.
MobSF-derived dynamic uses a flat-bonus approximation (not the weighted formula).

### 8.4 Dynamic Axis Conclusiveness

A run is **conclusive** when: BFCI ≥ 20, OR hook events / behavioural evidence records ≥ 1.

A run is **excluded** (`dynamic_exclusion_reason` set) when:
- `DYNAMIC_UNAVAILABLE` — sandbox never ran
- `NO_UI_RENDERED` — process started but no Activity/window appeared
- `EVASION_ONLY` — only anti-analysis events were seen
- `INSTRUMENTATION_FAILED` — Frida bridge failed
- `INSTALL_FAILED`, `TIMEOUT`, `FAILED` — infrastructure problems

Exclusion reason travels with `FRSBreakdown` so the analyst knows *why* the axis reads zero.

### 8.5 Banking Impact Score

```
BankingImpact = banking_targeting + (family_weight × 40) + regulatory_risk + campaign_bonus
```

Family severity weights:
`Drinik=1.0, Xenomorph=1.0, Cerberus=1.0, SOVA=1.0, Anubis=0.9, FluBot=0.9, Hydra=0.85, SpyNote=0.8, Joker=0.6, Unknown=0.5`

RBI MDS-2021 regulatory risk bonus: +20 (SMS interception + Indian bank targeting)
Active campaign from correlation: +15

### 8.6 Risk Bands

| Band | Score Range |
|---|---|
| Safe | < 25 |
| Low | 25–49 |
| Suspicious | 50–74 |
| High | 75–89 |
| Critical | ≥ 90 |

### 8.7 Verdict Flooring

- `verdict_floored_for_visibility`: concealed payload detected (limited static visibility)
- `verdict_floored_for_evasion`: STEI ≥ 50 but dynamic run inconclusive

## 9. VIDE – Visual Impersonation Detection Engine

**Location**: `shared/sudarshan_core/engines/vide/` (19 modules)

**Purpose**: Detect APKs impersonating Indian banking apps by comparing UI, colors, layout, DEX strings, and signing certificate against known-good baselines.

**Pipeline (`vide/pipeline.py`)**:
1. Extract `UIProfile`: layout XMLs (via APKTool decode dir), HTML assets, JS bundles, DEX strings
2. Signer check: `signer_registry.py` — compare APK signing certificate SHA256 against known-good hashes
3. Color palette comparison: `color_match.py`
4. Layout structure comparison: view AST (`view_ast.py`, `ast_builders.py`)
5. DEX string corpus comparison: `corpus_compare.py`
6. Aggregate verdict: flag when corpus score ≥ `CORPUS_DETECTION_THRESHOLD`
7. Optional semantic enrichment: `semantic_matcher.py` (calls Gemini advisory, does not change verdict)
8. Output: `VIDECompareResult` with `visual_impersonation_detected`, `confidence`, `attributed_institution`

**VIDE feeds into the BT axis** of STEI: when `visual_impersonation_detected=True`, BT score = `min(35 + confidence × 40, 85)`.

## 10. Findings and Evidence

### 10.1 Finding Types

| Type | Source | Key Fields |
|---|---|---|
| `ManifestFinding` | MobSF manifest_analysis | title, description, severity, regulation |
| `CodeFinding` | MobSF code_analysis | title, description, severity, reference |
| `ThreatScenarioRow` | Deterministic flag mapping (`risk_engine.py`) | indicator, threat_scenario, overlay_risk, credential_theft_risk, c2_risk, persistence_risk, confidence |
| `EvidenceMoment` | Agentic explorer | moment_type, title, description, screenshot_ids, severity |

### 10.2 Threat Scenario Table

`build_threat_scenario_table()` maps each active static flag to named threat scenarios:
- Each row has per-vector risk ratings: `overlay_risk`, `credential_theft_risk`, `c2_risk`, `persistence_risk`
- Confidence values are hard-coded per scenario type (e.g., SMS interception = 95)

### 10.3 Deduplication

No automatic cross-source deduplication. MobSF findings and Androguard flags may produce overlapping signals; they appear in separate UI sections.

### 10.4 AI and FRS Independence

The AI (`analyze_with_llm`) produces narrative and recommendations only. It does **not** generate findings that contribute to FRS. Scoring is always deterministic; AI enrichment occurs after scoring is finalized.

## 11. Database and Storage

**Technology**: SQLite via aiosqlite (WAL mode, `busy_timeout=5000ms`, `foreign_keys=ON`)
**Path**: controlled by `SUDARSHAN_DB_PATH` (default: `sudarshan.db`)

### 11.1 Schema

| Table | PK | Purpose |
|---|---|---|
| `users` | `id` | Analyst accounts (username, hashed_pw, role, created_at) |
| `cases` | `sha256` | Every analysis result (summary columns + full `raw_result` JSON) |
| `case_notes` | `id` | Analyst notes attached to a case |
| `analysis_jobs` | `job_id` | Async single-APK job queue |
| `ioc_cache` | `indicator+ioc_type` | IOC reputation cache with 24h TTL |
| `discovery_sessions` | `id` | APK URL discovery sessions |
| `discovery_candidates` | `id` | Discovered APK download candidates |
| `analysis_batches` | `batch_id` | Enterprise batch metadata |
| `analysis_batch_jobs` | `job_id` | Individual APK entries within a batch |

Cases store a full `raw_result` JSON blob in addition to typed summary columns.
Typed columns (final_risk_score, risk_band, dynamic_available, etc.) are indexed for fast list queries.
`raw_result` enables complete case reconstruction after restart.

### 11.2 In-Memory Report Cache

`OrderedDict` bounded to `SUDARSHAN_REPORT_CACHE_MAX=128` entries (LRU eviction).
Populated by `cache_report()` during analysis; read by all export endpoints.
Cases not in cache are reloaded from the DB `raw_result` column.

### 11.3 Artifact Storage

Dynamic analysis artifacts written to `sudarshan_artifacts/{sha256}/`:
- `screenshots/` — PNG captures
- `evidence.json` — evidence records
- `exploration_graph.json` — state graph
- `audit_log.json` — action audit trail
- `attack_timeline.json` — event timeline
- `manifest.json` — investigation manifest
- `coverage.json` — exploration coverage metrics

## 13. Authentication

- JWT Bearer tokens on all API endpoints (except `GET /` and `GET /health`)
- Roles: `analyst`, `soc_lead`, `admin`
- `require_analyst` FastAPI dependency: allows analyst + soc_lead + admin
- `soc_lead` and `admin` can view all cases; `analyst` sees only own cases
- Admin seeded on first boot from `ADMIN_USERNAME` / `ADMIN_PASSWORD` env vars
- If `ADMIN_PASSWORD` unset: a random password is generated and logged once
- Demo users (`soclead`, `analyst1`) optionally seeded via `SUDARSHAN_SEED_DEMO_USERS=true`
- Public registration: enabled by default in dev; disabled when `SUDARSHAN_ENV=production`
- Rate limiting via `slowapi`; disabled with `SUDARSHAN_RATE_LIMIT_DISABLED=true`

## 16. Error and Fallback Behavior

| Failure | Behavior |
|---|---|
| Analysis engine unreachable | WARNING logged; fallback to local Androguard-only pipeline or 503 (production) |
| MobSF unavailable | Androguard used exclusively; analysis continues |
| APKTool / JADX not installed | Skipped with non-critical warning |
| Frida / emulator not ready | Dynamic analysis skipped; `EMULATOR_UNAVAILABLE` recorded in FRS breakdown |
| Gemini API failure (agentic) | FallbackPlanner (deterministic) takes over; exploration continues |
| Gemini primary circuit open | Requests route to fallback provider automatically |
| Both Gemini providers failed | `GeminiAllProvidersFailed`; narrative degraded to minimal text |
| VT / OTX / AbuseIPDB keys missing | Correlation skipped; Correlation axis excluded from FRS |
| VIDE baseline not loaded | Empty VIDE result; BT axis uses package matching only |
| Evidence store import error | Evidence collection disabled; logged as warning |
| IOC cache not wired | Correlation re-queries APIs per analysis (no caching) |
