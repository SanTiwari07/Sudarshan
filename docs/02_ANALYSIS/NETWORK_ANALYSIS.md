# SUDARSHAN — Network Analysis & Traffic Capture

> **Classification:** AUTHORITATIVE  
> **Source Modules:** `shared/sudarshan_core/engines/network_capture.py`, `docker-compose.yml`  
> **Last Verified:** 2026-09-25  

---

## 1. Transparent Proxying via mitmproxy

To capture all outbound HTTP/HTTPS communications generated by suspected malware, SUDARSHAN deploys a `mitmproxy` sidecar container:

- **Host Binding:** `127.0.0.1:8085` (Loopback only — never exposed on public interfaces).
- **Container Port:** `8080`.
- **Operating Mode:** Transparent interception with automatic SSL certificate authority (CA) pre-installed into the Android guest sandbox.
- **Output:** Writes raw network flows directly to a shared Docker volume (`mitmproxy_har:/har/dump.har`).

---

## 2. Ingestion & Indicator Extraction

`NetworkCapture.ingest_mitmproxy_har()` parses the captured HAR stream:
1. **Flow metadata:** URL, method, response status, response size, and request headers (credential headers such as `Authorization` and `Cookie` are redacted to `[REDACTED]`).
2. **Request/response bodies are NOT parsed.** An earlier version of this document described POST-body inspection for exfiltrated SMS/contacts; that is not implemented.
3. **Correlation Feed:** Observed URLs reach the Threat Correlator through `network_flows` / `network_logs` in the dynamic result.

### Attribution to the correct analysis

The sidecar writes **one** HAR file for every analysis it proxies. A dynamic session constructs `NetworkCapture(session_started_at=...)`, and only HAR entries whose `startedDateTime` lies inside that session's window (±5 s) are attributed to it; entries outside the window or without a parseable start time are counted (`har_entries_out_of_window`, `har_entries_undated`) and excluded. Before this, the whole HAR was ingested, attributing other samples' traffic to the current one, and the analysis engine re-read it a second time unbounded.

### Frida hook flows

Hook-layer flows are endpoints the app reached (URL, or `IP:port` for native `connect()`), not inspected traffic. Native `connect()` flows are labelled `TCP_CONNECT` (they used to be labelled HTTP `GET`) and carry `ip`, `port`, `observation_count`, `first_seen`, `last_seen`, and `payload_inspected: false`.

### Disclosure

Every dynamic result carries `network_collection` (from `NetworkCapture.collection_report()`): whether a HAR was configured, found and attributed, `encrypted_traffic_inspected`, and plain-language `limitations`. When no HAR applies, the result, PDF report and dashboard state that **encrypted application traffic was not inspected**. Certificate-pinned traffic is never decrypted.
